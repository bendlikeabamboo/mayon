# Research: 012-easier-interaction-for-models

- **Claim**: the main chat context/system-prompt constructor is browser-free and already exercised by non-browser vitest tests: tests seed chats/settings through `repos` into a pglite DB (`useFileTestDb`), call `assembleContext(chatId)`, and assert on the assembled message list (branch cutoffs, brief/excerpt/attachment system notes). **Source**: `src/lib/chat/context.ts`, `src/lib/chat/context.test.ts` — 2026-10-31.
- **Claim**: quiz/lab prompt assembly is a pure function — `assemblePrompt(contract, instructions)` — over instructions read through `repos.settings` (`readCustomInstructions`, with a documented legacy-migration contract); covered by non-browser tests asserting the assembled system message byte-for-byte. **Source**: `src/lib/ai/generate/assembly.ts`, `src/lib/ai/generate/quiz.test.ts`, `src/lib/ai/generate/generate.test.ts`, `docs/history/appendices/020-prompt-settings-contract.md` — 2026-10-31.
- **Claim**: the repo already simulates model behavior deterministically without an API key: a mock-llm fixture system (`tests/fixtures/mock-llm/` — `server.mjs` e2e mock server, classification markers pinned to product constants, quiz/lab fixtures) backs non-browser tests of full generation flows; grew out of specs/017-mock-llm-chat-tests (ideas/004). What no layer covers today is prompt _quality_ judgment by a real model. **Source**: `src/lib/ai/generate/classification-markers.test.ts`, `tests/fixtures/mock-llm/*`, `docs/history/index.qmd` (ideas/004 row) — 2026-10-31.
- **Claim**: the core architecture invariant ("app code calls repositories only; `db` private to `src/lib/db/`") is documented (AGENTS.md, `docs/reference/seams.qmd`) but **not machine-enforced** — `eslint.config.js` carries no import-boundary / `no-restricted-imports` rules; nothing fails lint if a component imports `db` directly. The seam's authority is purely conventional. **Source**: `eslint.config.js` — 2026-10-31.
