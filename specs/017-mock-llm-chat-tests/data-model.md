# Data Model: Mock-LLM Chat Test Suite

Phase 1 output. Entities of the **test stack** only — no product schema changes. The
product entities exercised (ProviderConfig, IndexedDB key records, conversations,
messages) are read about in `docs/dev/architecture.qmd` and are listed here only as
boundaries the suite touches.

## Entities

### MockLlmService

The stand-in LLM. Stateless; lives only in the test stack.

| Attribute | Value | Notes |
|---|---|---|
| runtime | plain `node:http`, zero dependencies (`tests/fixtures/mock-llm/server.mjs`) | Node 22 in the compose `mock-llm` service |
| port | fixed internal port (compose `expose`, no host port) | reachable as `http://mock-llm:<port>` from `server` only |
| endpoints | `POST {base}/chat/completions`, `GET {base}/models` | base = `http://mock-llm:<port>/v1`; see [contracts/mock-llm-api.md](contracts/mock-llm-api.md) |
| reply source | `kitchen-sink.md` fixture file, loaded at startup | one document, served to every chat request |
| request modes | SSE (`stream: true`) and single JSON (no `stream`) | mode detected per request; concurrent requests supported (D7) |
| auth behavior | ignores `Authorization` | placeholder key arrives via proxy; client-side requirement only |

State transitions: none (stateless). Healthcheck: TCP accept on its port.

### KitchenSinkFixture

The deterministic reply document and single source of truth for rendering assertions.

| Attribute | Value |
|---|---|
| format | CommonMark + GFM, authored to pass the product's sanitize schema |
| content inventory | headings, lists (incl. task lists), tables, blockquotes, links, inline + display KaTeX math, one `mermaid` fenced block, ≥2 code blocks in different languages, alignment-friendly prose paragraphs |
| offsets | raw-markdown offsets are stable by construction (static file); the suite asserts source alignment through the product's sourcemap + DOM alignment |
| alignment safety | no raw HTML; content that maps to injected chrome (math, mermaid, copy buttons) is positioned so `EXCLUDED_CHROME_SELECTORS` (`src/lib/chat/selection.ts:27-36`) fully accounts for it |
| maintenance | manual: new renderer capabilities require extending this document (accepted drift, spec Assumptions) |

Relationships: served verbatim by MockLlmService; asserted against by the ChatE2ESuite.

### ProviderProfileForTests

The provider identity the suite onboards — a real `ProviderConfig` created through the
real UI, not a separate entity.

| Attribute | Value | Product field |
|---|---|---|
| template | "LiteLLM (self-hosted)" (`discoverable: true`) | `registry.ts:126-137` |
| kind | `openai-compatible` | `ProviderConfig.kind` |
| baseUrl | `http://mock-llm:<port>/v1` | `ProviderConfig.baseUrl` |
| defaultModel | `mock-sink` (matches `/models` payload) | `ProviderConfig.defaultModel` |
| key | fixed placeholder string (`e2e-placeholder-key`) | IndexedDB `mayon/providerKeys` via the real "Save key" flow |
| active | set active before sending | `activeProvider` setting |

Validation rules inherited from the product: key mandatory for this kind
(`kindRequiresKey`); extra-body/sampling defaults untouched; tool capability resolves
off for a non-allowlisted base URL.

### ChatE2ESuite

The Playwright project and its wiring.

| Attribute | Value |
|---|---|
| location | `tests/e2e/` + root `playwright.config.ts` |
| baseURL | `http://localhost:5173` (dev `web` container) |
| specs | `onboard.spec.ts` (P1 round trip), `render.spec.ts` (P2 rendering coverage) |
| shared fixture | Playwright test fixture that performs onboarding once per worker and exposes the onboarded chat page |
| boot discipline | every test waits out the BootGate (server `pg` cap advertised) before interacting — no product shortcuts |
| scripts | `pnpm test:e2e` (new); existing Vitest scripts untouched |
| CI | new `e2e` job in `.github/workflows/ci.yml` (see [contracts/e2e-stack.md](contracts/e2e-stack.md)) |

## Entity relationships (test-stack view)

```text
ChatE2ESuite --drives--> product UI (settings → chat) --creates--> ProviderProfileForTests
ProviderProfileForTests --sends via--> /api/llm/proxy --forwards to--> MockLlmService
MockLlmService --replies with--> KitchenSinkFixture
ChatE2ESuite --asserts against--> KitchenSinkFixture (rendered DOM + source offsets)
```

## Boundaries (exercised, never modified)

- Postgres `settings` rows `providers` / `activeProvider` (via the app's repositories)
- IndexedDB `mayon` v1 store `providerKeys` (via the app's keystore)
- `search_vec` generated columns: untouched, per constitution (no reindex paths)
- Drizzle migrations: none generated by this feature
