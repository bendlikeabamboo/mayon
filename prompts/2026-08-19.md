I want to change my approach on how the application treats elements in the chat interface.

So right now it's a bit mixed bag but I want to standardize it. But before doing so I'd like to verify my current assumptions.

Right now the chat interface is divided into I think 3 categories, the user input, the LLM output and the tool call results.

However, there are a couple of things I don't like.

For example:

1. I'm having a case where the tool call result is being displayed and it can be a wall of text that's hard to read.
2. Reasoning tokens are attached to the non-reasoning reply of the LLM. Which is okay, not a problem, but it creates sort of this parent child entity.

So I thinking of an approach that standardizes everything into unified entity. For example
1. User chat
2. LLM Reasoning
3. LLM Output
4. MCP Permission Prompt
5. MCP Result
6. Tool Call
7. Tool Result
8. Choices?
9. What else? (there could be more)

Then these entities will have these properties:

Types
1. User initiated
2. LLM Internal Process
   1. Could be used for reasoning, or it's calling MCP on its own and it's basing it's next turn on the result of that
3. LLM External (the one it sends to the user)

Then based on the type (and you can change what we call it huh, maybe type is too generic), if it's user initiated then it belongs on the right, with the foreground color, if it's llm internal process it doesn't have a bounding box and it's on the left part. if it's LLM external then it's on the left part also but with a bounding box.

Collapsible
1. True
2. False

If we can collapse the text

collapsed_by_default
1. True
2. False

This way, the reasoning tokens will have it's own mini-line in the llm internal space, the tool call will have it's own line in the llm internal process, etc.
